4. Terms🔗

Cvc.lean exposes two API-s for terms: Typed and Untyped. The former provides very strong static guarantees by strongly-typing terms; the latter does not but is more flexible, allowing in particular to build lists/arrays of terms of different sorts.

NB: cvc.lean enforces type-safety through definition irreducibility, which means you need to use Lean's module system to get any of its benefits.

4.1. Typed Terms🔗

🔗def
Cvc.Typed.Term [Ω] : Type → Type
Cvc.Typed.Term [Ω] : Type → Type

A cvc5 term whose sort is the one the Lean type α denotes.

Term Int, Term (Set Bool) and Term (Int → Bool) are terms of the SMT-LIB sorts Int, (Set Bool) and (-> Int Bool); a Lean type denotes a sort through its ToTyp instance. Every constructor states its sorts through the index, so a sort mistake is a Lean type error rather than a cvc5 error at runtime, and a value read out of a model comes back as an α.

The index is phantom: at runtime a Term α is exactly a Cvc.Untyped.Term. erase goes down for free, and Cvc.Untyped.Term.typeCheck goes up by checking the term's sort.

Typed terms have a type parameter for the actual Srt of that term. We saw previously that ToTyp links types to Srt-s, and it is precisely the mechanism used here. Typing terms lets us check statically that term constructors are invoked in a valid way, and makes their signature as precise as it can be.

4.1.1. Examples🔗

Examples of using term constructors follow, feel free to hover around to make sure the terms are correctly typed.

open Typed in conj := (and b1 b2) i1_pos := (<= 0 i1) ite := (ite (<= 0 i1) i1 i2) #eval Env.runIO do let b1 ← Term.mkSymbolAs Bool "b1" let b2 ← Term.mkSymbol "b2" let conj ← b1.and b2 println! "conj := {conj}" let i1 ← Term.mkSymbol "i1" let zero ← Term.mkInt 0 let i1_pos ← zero.le i1 println! "i1_pos := {i1_pos}" let i2 ← Term.mkSymbol "i2" let ite ← i1_pos.ite i1 i2 println! "ite := {ite}" 
conj := (and b1 b2)
i1_pos := (<= 0 i1)
ite := (ite (<= 0 i1) i1 i2)

Strong-typing works with functions/function application as well.

open Typed in f : (-> Int Bool Int) := f f_i : (-> Bool Int) := (f i) f_i_b : Int := (f i b) f_i_b' : Int := (f i b) #eval Env.runIO do let f ← Term.mkSymbolAs (Int → Bool → Int) "f" println! "f : {← f.getSort} := {f}" let i ← Term.mkSymbol "i" let f_i ← f.apply i println! "f_i : {← f_i.getSort} := {f_i}" let b ← Term.mkSymbol "b" let f_i_b ← f_i.apply b println! "f_i_b : {← f_i_b.getSort} := {f_i_b}" -- alternatively let f_i_b' ← f.apply2 i b println! "f_i_b' : {← f_i_b'.getSort} := {f_i_b'}" 
f : (-> Int Bool Int) := f
f_i : (-> Bool Int) := (f i)
f_i_b : Int := (f i b)
f_i_b' : Int := (f i b)

Of course, type-checking catches any invalid-sort mistake we make.

open Typed in #eval Env.runIO do let b1 ← Term.mkSymbolAs Bool "b1" let b2 ← Term.mkSymbolAs Int "b2" let conj ← b1.and Application type mismatch: The argument b2 has type Term Int but is expected to have type Term Bool in the application b1.and b2 Note: The following definitions were not unfolded because their definition is not exposed: Term ↦ 6b2 println! "conj := {conj}"

Another type-checking error on a ill-typed function application:

open Typed in #eval Env.runIO do let f ← Term.mkSymbolAs (Bool → String → Rat) "f" let b1 ← Term.mkSymbolAs Bool "b1" let i1 ← Term.mkSymbolAs Int "i1" let f_b1_i1 ← f.apply2 b1 Application type mismatch: The argument i1 has type Term Int but is expected to have type Term String in the application f.apply2 b1 i1 Note: The following definitions were not unfolded because their definition is not exposed: Term ↦ 6i1 println! "f_b1_i1 := {f_b1_i1}"

4.2. Untyped Terms🔗

🔗def
Cvc.Untyped.Term [Ω] : Type
Cvc.Untyped.Term [Ω] : Type

A sort-erased cvc5 term.

The term carries no sort on the Lean side: its sort is known to cvc5 alone, so a sort mistake, such as and applied to an integer, is reported by cvc5 at runtime. In exchange, terms of different sorts share one type, and an Array Term can hold them side by side.

A term belongs to the Ω scope it was built in and cannot leave it. At runtime it is exactly a cvc5 term, so the wrapper costs nothing. typeCheck checks its sort against a Lean type and gives it that type as an index, producing a Cvc.Typed.Term.

Untyped terms do not have a type parameter corresponding to their sort, which means untyped term constructors do not provide any static guarantee that the result is a valid term. Instead, invalid terms will fail at runtime.

4.2.1. Examples🔗

Below is the untyped version of the first typed-term example. No type-inference can take place, so we must always specify what the sort of each symbol is.

open Untyped in conj := (and b1 b2) i1_pos := (<= 0 i1) ite := (ite (<= 0 i1) i1 i2) #eval Env.runIO do -- specify the sort using Lean types... let b1 ← Term.mkSymbolAs Bool "b1" -- ...or using `Srt` values let bool ← Srt.bool let b2 ← Term.mkSymbol bool "b2" let conj ← b1.and b2 println! "conj := {conj}" let i1 ← Term.mkSymbolAs Int "i1" let zero ← Term.mkInt 0 let i1_pos ← zero.le i1 println! "i1_pos := {i1_pos}" let i2 ← Term.mkSymbolAs Int "i2" let ite ← i1_pos.ite i1 i2 println! "ite := {ite}" 
conj := (and b1 b2)
i1_pos := (<= 0 i1)
ite := (ite (<= 0 i1) i1 i2)

Since no type-checking is taking place, we can compile invalid terms without issue.

section variable [Ω] open Untyped def badTerms : Env Unit := do let b1 ← Term.mkSymbolAs Bool "b1" let b2 ← Term.mkSymbolAs Int "b2" let conj ← b1.and b2 println! "conj := {conj}" end
