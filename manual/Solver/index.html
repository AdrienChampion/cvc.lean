6. Solver🔗

Similar to terms, solvers come in typed and untyped flavors, though they do not differ by much. The main differences are

  • typed Solver.assert requires a Term Bool, instead of a Term for the untyped version, and

  • typed model/value-retrieval as we will see below.

The rest of this section discusses typed solvers.

Solvers are tied to cvc5's notion of term manager, which means they are manager-scoped with a Cvc.Ω instance just like sorts and terms.

open Cvc Typed variable [Ω]

6.2. Check-sat and modal environments🔗

The check-sat function is significantly more complex, to see why let us look a the get-value function first.

🔗def
Cvc.Typed.Solver.getValue [Cvc.Ω] (s : Cvc.Typed.Solver) {α : Type}
  [Cvc.Typed.TermToValue α] (term : Cvc.Typed.Term α) : s.EnvSat α
Cvc.Typed.Solver.getValue [Cvc.Ω]
  (s : Cvc.Typed.Solver) {α : Type}
  [Cvc.Typed.TermToValue α]

The value the model gives a term, as the Lean value its index describes.

Since retrieving the value of a term is only legal (directly) after a check-sat that returned sat, cvc.lean strongly-types this fact with a modal environment, i.e. a monad specific to a solver being in sat-mode.

Cvc.Typed.Solver.getTimeoutCore [Cvc.Ω] (s : Cvc.Typed.Solver) :
  s.EnvUnknown (Cvc.Typed.Result × Cvc.Typed.Terms Bool)
Cvc.Typed.Solver.getTimeoutCore [Cvc.Ω]
  (s : Cvc.Typed.Solver) :
  s.EnvUnknown
    (Cvc.Typed.Result ×
      Cvc.Typed.Terms Bool)

Get a timeout core.

This function computes a subset of the current assertions that couse a timeout. It may make multiple checks for satisfiability internally, each limited by the timeout value given by timeout-core-timeout.

If the result is unknown and the reason is timeout, then returned the set of assertions corresponds to a subset of the current assertions that cause a timeout in the specified time timeout-core-timeout. If the result is unsat, then the list of formulas correspond to an unsat core for the current assertions. Otherwise, the result is sat, indicating that the current assertions are satisfiable, and the returned set of assertions is empty.

(get-timeout-core)

Warning: this function is experimental and may change in future versions.

6.3. More check-sat functions🔗

For simple check-sat use cases where the only thing that matters is whether the current assertions are satisfiable or not one can simply use Solver.checkIsSat.

🔗def

Checks the satisfiability of the constraints asserted so far.

Oftentimes we want to return a result specific to a sat/unsat result, and nothing otherwise, for instance a model on a sat result and nothing on unsat. In such cases it can be easier to use Solver.checkSat? which lets the caller specify which outcome produces a result and how, the unexpected result producing none by default.Marginal noteOn an unknown outcome, the default throws an error instead of returning none as unknown is considered to never be expected by default.

6.4. Defining (recursive) function symbols🔗

Unlike declaring a function symbol, defining one is a solver-specific action as it implies a solver-level constraint to tie the symbol and its definition together.

Defining a function symbol in a solver is very similar to building a lambda: the resulting term must be typed from its bound variables.

6.4.1. Mutually recursive function symbols🔗

Cvc.lean does not, currently, expose special functions for defining mutually recursive functions in its typed API. The untyped API does, which is what we present below.

open Cvc Untyped variable [Ω] forcing even sat, i := 4 forcing odd sat, i := 3 #eval Env.runIO do let int ← Srt.int let bool ← Srt.bool let solver ← Solver.new solver.setOption "produce-models" "true" solver.setOption "fmf-fun" "true" let even ← solver.declareFun "even" #[int] bool let odd ← solver.declareFun "odd" #[int] bool let n ← Term.mkBVar int "n" let m ← Term.mkBVar int "m" solver.defineFunsRec #[even, odd] #[#[n], #[m]] #[ ← smt! if n ≤ 0 then n = 0 else odd (n - 1), ← smt! if m ≤ 0 then false else even (m - 1)] let i ← Term.mkSymbol int "i" smt! 3 ≤ i >>= solver.assert println! "forcing even" solver.checkSat (assuming := #[← smt! even i]) (ifSat := do println! " sat, i := {← i.getValue}") println! "forcing odd" solver.checkSat (assuming := #[← smt! odd i]) (ifSat := do println! " sat, i := {← i.getValue}")
