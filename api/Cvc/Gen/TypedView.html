    Generating typed views #

    A theory's typed view is indexed by the sort it takes apart: Cvc.Typed.View.Arith : Typ → Type. It is built in two layers.

    • Parts. For each sort the theory's operators produce, an inductive of those operators: View.Arith.OnBool, OnInt, OnRat, and OnAny β for those producing a type variable — ite, or add at {α : IsArith}. A constructor has its operator's indices, then the size and type variables its result does not fix, read off the kids' sorts, then implicit proofs — a type variable's classes as the Typ predicate each stands for, a computed result's equation with the part's parameter, n + m = w for a concatenation — then its kids, typed. A kid whose sort mentions a type variable is indexed by Typ.Denote of that sort.
    • The theory view, one constructor per part, at the part's sort: bool (v : OnBool) : View .bool, bitVec (w) (v : OnBitVec w) : View (.bitVec w), any (v : OnAny τ.Denote) : View τ. Matching an operator refines the sort to the part's; a compound result's equation stays a proof field inside the part, so matching never unifies against anything but a sort's head.

    The viewer, View.Arith.of, converts the theory's sort-erased view: that has read the kind, the kids and the indices, and the typed view adds what the sort adds — the sort fields, read off the kids, and the proofs. It answers none where it cannot: a kid whose sort no Typ describes, a sort that does not fit the operator.

    • gen_typed_view% from <Spec module> generates and registers a theory's typed view.
    • register_typed_view% <View> [ctor KIND, …] registers a hand-written one, whose constructors are the theory view's own.
    • def.typed_term_view V — def.term_view V under open Cvc.Typed — generates the aggregate V : Typ → Type: the leaves, a variant of<Theory> per theory, other, one @[match_pattern] abbreviation per operator, a viewer V.of, and a ViewFamily instance.
