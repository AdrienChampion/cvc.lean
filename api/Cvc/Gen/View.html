    Generating views #

    A view takes a term apart one level: its operator, as a constructor, and its kids. Each theory has its own view, generated from its specification beside its constructors — or, for what no specification describes, written by hand and registered — and def.term_view V gathers the views of every theory the current module imports into one inductive.

    • gen_untyped_view% from <Spec module> generates a theory's sort-erased view, an inductive with one constructor per operator, and its viewer of?, then registers it.
    • register_untyped_view% <View> [ctor KIND, …] registers a hand-written one.
    • def.untyped_term_view V — def.term_view V under open Cvc.Untyped — generates the aggregate V: the leaves, a variant of<Theory> per registered view, a catch-all other, one @[match_pattern] abbreviation per operator so that a pattern can skip the theory, a viewer V.of, and a TermView instance.

    Which theories def.term_view gathers is decided by the registry, which holds exactly the views of the modules imported: importing a theory is what makes its operators visible.

    Like Cvc.Gen.Term, this module imports neither layer: every name the generated code mentions is built with mkIdent, fully qualified.
