    The Lean type a sort denotes #

    Typ.Denote τ is the Lean type that indexes terms of sort τ: .int denotes Int, .set .int denotes Set Int, a record its Record, a tuple its product. It is what makes a sort carried as data — a Typ field of a term's view — usable as a term's index: matching the Typ refines Term τ.Denote to Term Int, definitionally.

    A sort with no better denotation denotes Sorted τ, a stand-in indexed by the sort itself: declared sorts, a container keyed on something with no order, a tuple whose last component is a tuple. A term at a stand-in is moved to a user's own index with Typed.Term.cast.

    Everything here is reducible and exposed, so that a known Typ reduces both in unification and in instance resolution.

          def Cvc.Typ.denoteWithOrd :
          Typ → (T : Type) × Option (Ord T)

          The Lean type a sort denotes, together with its order if it has one.

          Computed together because a container's denotation needs its element's order: .set .int denotes Set Int, which is only a type given Ord Int. A container whose element has no order — a set of functions — denotes Sorted τ, as do declared sorts. TotalMap and functions have no order of their own; a record or a tuple has one exactly when all its components do, lexicographically, as OrdFields and the product order give it.

              def Cvc.Typ.denoteProdWithOrd :
              List Typ → (T : Type) × Option (Ord T)

              A tuple's denotation: the right-nested product of its components', as α × β × γ indexes a three-component tuple, and OneTuple for one component; ordered if every component is.

              A tuple whose last component is itself a tuple has no product to denote it — the product would flatten it — and neither has the empty tuple: those are Sorted.

                      @[reducible]
                      def Cvc.Typ.Denote (τ : Typ) :
                      Type

                      The Lean type a sort denotes.

                      It reduces on a known Typ, which is what makes matching on a view's Typ refine the kids' index: Term (Typ.Denote .int) is Term Int, and Term (Typ.Denote (.set .int)) is Term (Set Int), with the very Ord Int a user's Set Int has.

                      Reducible, as is everything it is computed with, so that instance resolution sees through it too: a record's FieldOf instances are found on the field list it reduces to.

                      Equations
                      • τ.Denote = τ.denoteWithOrd.fst

                          def Cvc.delabDenote :
                          Lean.PrettyPrinter.Delaborator.Delab

                          Shows a denotation, or a function type over denotations, as the type it reduces to.

                          Typ.Denote (.set .int) is Set Int, and a reader should see Set Int. It reduces by dsimp with the denotation's own definitions only: whnf would also unfold Set, an abbreviation, and show Std.TreeSet Int compare. A sort bound by an unmatched pattern does not reduce, or only part-way: the guards hand it back to the default printer, τ.Denote, rather than show it stuck inside denoteWithOrd — and without them the delaborator would re-enter itself forever.
