    SyGuS grammars, typed #

    A grammar restricts the shape of a term the solver may produce. Two things about one go wrong easily, and both are stated in the types here.

    A rule must have its non-terminal's sort — cvc5 answers expected ntSymbol and rule to have the same sort, which addRule turns into a type error.

    A grammar's parameters must be the very same variables the synth-fun is declared with. In SyGuS they are one thing, (synth-fun f ((x Int)) Int G), but two arguments in the API, so this Grammar carries its own parameters and synthFun takes nothing else. Its index is the signature the grammar can generate: Grammar (bvs.signatureTo α), folded exactly as Solver.defineFun folds its own parameters. With no parameters that is just the start symbol's sort, which is the shape getInterpolant and getAbduct want.

    A grammar is built through a solver, s.mkGrammar, but belongs to the scope as a term does: any solver of the scope accepts it.

    A grammar freezes once it is used, as in the sort-erased layer: the rule builders answer a new Grammar, but the object underneath is shared and cvc5 rejects further rules after synthFun.

    Non-terminal symbols #

    source
    structure Cvc.Typed.NT [Ω] (α : Type) :
    Type

    A grammar's non-terminal symbol, at the sort its index describes.

    A bound variable, but not interchangeable with one: mkGrammar takes the parameters and the non-terminals separately, and only the type keeps them apart.

    A structure rather than an alias, for the same reason as the sort-erased one: a def wrapper would need Term exposed, and that would make the two layers the same type downstream. One field, so it costs nothing at runtime.

                          Grammars #

                          The type is declared beside Solver, whose interpolant and abduct queries take one; what is here builds one. Like a term, a grammar belongs to the scope rather than to the solver that built it.

                            def Cvc.Untyped.Grammar.typeCheckAs [Ω] (σ : Type) [ToTyp σ] (g : Grammar) :
                            Env (Typed.Grammar σ)

                            Types a sort-erased grammar at signature σ, checking it against what the grammar generates.

                            The grammar counterpart of Untyped.Term.typeCheckAs. σ is compared with the grammar's Untyped.Grammar.signatureSrt: its parameters' sorts arrowed onto its start symbol's, or the start symbol's sort alone when there are no parameters. Arrows flatten, so a one-parameter grammar whose start symbol is a function checks against the same σ as a grammar taking those arguments as parameters; that is harmless, the typed grammar keeping the parameters it was actually built with.

                                        smt.grammar! #

                                        The syntax is declared beside the sort-erased grammar; this is the typed expansion, and the scoped smt.grammar! that open Cvc.Typed selects. A sort is the Lean type of the non-terminal's or the parameter's index, and the result is Grammar σ with σ the parameters folded over the start sort, exactly what Solver.mkGrammar answers.

                                        smt.mkGrammar! and smt.letGrammar! answer the parameters as BVar α and the non-terminals as NT α, each at its declared index, so a rule added afterwards is checked against its non-terminal's sort, and a parameter passed where a non-terminal is wanted does not typecheck.
