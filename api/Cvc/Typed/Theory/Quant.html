    Quantifiers, typed #

    A quantified formula is a Term Bool whatever it binds, and so is its body. Two spellings are offered, as sort-erased.

    • mkForall/mkExists take the bound variables as a BVars spine, as BVars.lambda does.

    • forallH/existsH take the body as a Lean function of the variables. Here each variable's sort comes from the type of its argument, so a quantifier reads like a Lean one:

      Term.forallH fun (x y : Term Int) => smt! x + y = y + x

    A quantifier binds at least one variable: an empty spine is ruled out by an autoparam, and a body taking no argument has no Binder instance.

        Binding through Lean functions #

        Binder φ says that φ is the type of a quantifier's body written as a Lean function: one Term α argument per bound variable, ending in Env (Term Bool). The variable's sort is α's. There is no instance for a bare Env (Term Bool), so a body binding no variable does not typecheck.

        The arguments' types are what the sorts come from, so they must be known: write fun (x : Term Int) => … rather than fun x => … when nothing else in the body pins them down.

                Viewing a quantifier #

                Quantifiers are hand-written rather than specified, so their view is too. The variables' sorts are a list of Typs, as an application's arguments are, and the body mentions the variables: walking into it meets them as the aggregate's bvar leaf.
