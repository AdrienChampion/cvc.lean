    Folding over terms, and walking them with a zipper #

    Term.fold visits a term's nodes; Term.walk visits them through a zipper and can replace them. Both hand each node to the user as its view, the inductive def.term_view V generates, and both take two optional functions: pre, called on reaching a node, before its kids, and post, called on leaving it, after them. Each answers what to do next — descend, skip the kids, stop, and for a walk replace the node — along with the new state.

    fold runs in any monad. Taking a term apart is pure, and the only failure, an ill-formed term, is one cvc5 never builds. walk needs Env, to rebuild what it replaced under: building a term goes through the term manager.

    The machinery is written once, here, and shared with the typed layer: the zipper carries a payload per node, which the typed layer uses for each node's sort, and foldWith/walkWith take how a node is presented to the user's functions.

        What a walk does on reaching a node, before its kids. R is what replaces the node.

        • descend {σ R : Type} (s : σ) : WalkPre σ R

          Visit the kids.

        • skip {σ R : Type} (s : σ) : WalkPre σ R

          Do not visit the kids; the node is still left, post and all.

        • replace {σ R : Type} (t : R) (s : σ) : WalkPre σ R

          Replace the node, without visiting the replacement; it is then left.

        • replaceAndRevisit {σ R : Type} (t : R) (s : σ) : WalkPre σ R

          Replace the node and visit the replacement, from pre.

        • stop {σ R : Type} (s : σ) : WalkPre σ R

          End the walk, keeping every replacement made.

                    The zipper #

                    A position in a term: the focus, and the path back to the root. Each node carries a payload P, computed when the zipper reaches it — nothing for the sort-erased Zipper, its sort for the typed one. Nothing about the path is at the type level: an edit replaces the focus by a term of the same sort, so every ancestor keeps its sort.

                                                            Walks a term's nodes through a zipper, in depth-first order, replacing some.

                                                            The same order as Term.fold, and the same two optional functions, each handed the zipper focused on the node — so it sees the node's context too — and its view, and answering whether to replace it. A replacement must have the sort of the node it replaces, which is checked. post sees a node rebuilt with its replaced kids. Answers the rebuilt term with the final state, stop included.
