    What sort-erased views are built from #

    A view takes a term apart one level: its operator, as a constructor, and its kids. Each theory has one, generated from its specification beside its constructors (gen_untyped_view%) or written by hand for what no specification describes, and def.term_view V gathers the views of every imported theory into one inductive V, with the leaves — values, symbols, bound variables — and a catch-all. This module holds what those need.

    Taking a term apart is pure: its kind, kids and indices are read without Env. The only failure is an ill-formed term, which cvc5 never builds, so a view does not answer an error for it.
