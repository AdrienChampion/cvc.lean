    The sort-erased term type #

    A term carries no sort on the Lean side: it is exactly a cvc5 term, so the wrapper is a zero-cost def and the conversions either way are id. def3% derives the comparison and printing instances from the underlying type.

    Cvc.Untyped.Term names both this type and the namespace holding the generated constructors. Being a declaration as well as a namespace is what lets a typed generation site write

    open Cvc renaming Untyped.Term → T

    and have the generator's T.<id> delegation resolve.

              def Cvc.Untyped.Term [Ω] :
              Type

              A sort-erased cvc5 term.

              The term carries no sort on the Lean side: its sort is known to cvc5 alone, so a sort mistake, such as and applied to an integer, is reported by cvc5 at runtime. In exchange, terms of different sorts share one type, and an Array Term can hold them side by side.

              A term belongs to the Ω scope it was built in and cannot leave it. At runtime it is exactly a cvc5 term, so the wrapper costs nothing. typeCheck checks its sort against a Lean type and gives it that type as an index, producing a Cvc.Typed.Term.

                        Substitution #

                        cvc5 substitutes simultaneously and once: the sources are matched in a single pre-order pass, so a replacement is never itself rewritten, and the result is not driven to a fixed point. Substituting x by g z in f x y gives f (g z) y even when z is also a source.

                        source
                        def Cvc.Untyped.Term.substitute' [Ω] (t : Term) (src tgt : Terms) (valid : Array.size src = Array.size tgt := by (try grind) <;> fail "failed to prove there are as many replacements as sub-terms") :
                        Env Term

                        Simultaneously replaces each src[i] by tgt[i] throughout t.

                        A source may be any sub-term, not only a variable, and one that does not occur leaves the term unchanged. Where src holds duplicates the earliest wins. cvc5 reads the two arrays as a 1:1 mapping, which is what valid keeps true.

                        substitute is the same thing over pairs and is usually the one to reach for; this form exists because the two arrays are what cvc5 takes.
