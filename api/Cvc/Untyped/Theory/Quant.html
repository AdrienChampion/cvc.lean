    Quantifiers, sort-erased #

    A quantified formula binds its variables the way a lambda does: they are BVars gathered into a variable list, and the body mentions them as ordinary terms. Two spellings are offered.

    • mkForall/mkExists take the bound variables explicitly, as BVars.lambda does.
    • forallH/existsH take the body as a Lean function of the variables, so that no BVar is ever written by hand. The H is for higher-order abstract syntax: binding is borrowed from Lean's own fun.

    A quantifier binds at least one variable, cvc5 rejecting an empty variable list. Asserting a quantified formula needs a logic with quantifiers, such as the default ALL; a QF_ logic rejects it.

    cvc5's WITNESS binder is deliberately not wrapped: asserting a term that contains one aborts the process rather than raising an error.

                smt! #

                smt! ∀ (x y : s) (b : t), body and smt! ∃ … are Lean's own quantifier syntax, binders in parentheses as fun takes them (smtQuantBinder, declared in Cvc.Ext). What follows the colon depends on the layer: here it is a Lean type (Int) or a Srt value (int), as wherever the sort-erased DSL takes a sort; typed, it is the Lean type the variable's index is, and only that.

                The body extends as far right as it can, as in Lean, so a quantifier in argument position needs parentheses. Expansion goes through forallH/existsH, binding each variable under the name the writer gave it, which is also the name cvc5 prints.
