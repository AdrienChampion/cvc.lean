    SyGuS grammars, sort-erased #

    A grammar restricts the shape of a term the solver is allowed to produce — the candidates a synth-fun may return, or the shape of an interpolant or abduct.

    Two kinds of variable go into one: the parameters the synthesized term may mention, and the non-terminals the rules are written over. cvc5 takes both as plain bound variables, which makes them trivial to mix up, so a non-terminal has its own type here. NT converts to a term, because a non-terminal appears inside its own rules, but not to a BVar: handing one to mkGrammar as a parameter is exactly the mistake worth ruling out.

    A grammar freezes once it is used. addRule and friends answer a new Grammar, so the type reads as though grammars were persistent values, but the object underneath is shared: once a grammar has been passed to synthFun, cvc5 rejects every further rule with Grammar cannot be modified after passing it as an argument to synthFun. Build a grammar completely before using it.

                    Grammars #

                    A grammar belongs to the scope, as a term does: cvc5 builds one through a solver, but any solver of the same term manager accepts it. The type is declared beside Solver, whose interpolant and abduct queries take one; what is here builds one.

                    source
                    def Cvc.Untyped.Solver.mkGrammar [Ω] (s : Solver) (boundVars : BVars) (start : NT) (others : NTs := #[]) :
                    Env Grammar

                    A grammar over the given parameters, starting at start.

                    boundVars are the parameters of the synth-fun this grammar will constrain, and must be the very same variables that function is declared with. others are the further non-terminals the rules may mention: every one has to be declared here, since a rule over an undeclared symbol is rejected.

                    The start symbol is a separate argument rather than the head of one array, because cvc5 takes the first non-terminal as the start symbol and then drops whatever is unreachable from it — silently. Handing it #[cnd, start] instead of #[start, cnd] yields a grammar containing neither start nor its rules, with no error. Naming the start symbol makes that unrepresentable, and makes the array's non-emptiness structural rather than a side condition.

                                  smt.grammar! #

                                  A grammar written as one block, BNF-style, with smt! terms as its alternatives:

                                  smt.grammar! s (x y : Int) where
  start : Int  := x | y | if cnd then start else start
  cnd   : Bool := start ≤ start
                                  • s is a solver to build the grammar with — any solver of the scope will do, a grammar belonging to the scope rather than to a solver; the binders after it are the grammar's parameters.
                                  • Each line declares a non-terminal and its sort, then its alternatives separated by |. The first line's is the start symbol.
                                  • Inside the alternatives a non-terminal or parameter stands for its term, so rules mention one another and themselves freely. Every non-terminal is made before any rule is added.
                                  • ?const and ?var are cvc5's "any constant" and "any parameter" of the non-terminal's sort.

                                  A sort is written as a Lean type or a Srt sort-erased, and as a Lean type typed — the typed smt.grammar! being an ordinary Grammar whose index is the parameters folded over the start sort.

                                  Extending a grammar afterwards #

                                  smt.grammar! answers the grammar alone, its parameters and non-terminals being made out of sight, so nothing can be added to it later. Two forms with the same body answer them too:

                                  • smt.mkGrammar! s … where … answers grammar × NT₁ × NT₂ × … without parameters, and (grammar × PARAM₁ × …) × NT₁ × NT₂ × … with some, in declaration order. The parameters are grouped with the grammar so that one cannot be taken for a non-terminal by position.

                                  • smt.letGrammar! g ← s … where … is a do element binding g, the parameters and the non-terminals under the names the block declares, so the order cannot be got wrong:

                                    smt.letGrammar! g ← s (x y : Int) where
  start : Int  := x | y
  cnd   : Bool := start ≤ start
let g ← g.addRule start (← smt! if cnd then start else start)

                                    A parameter is bound as a BVar and a non-terminal as an NT, both converting to terms. The names are bound without a source position, so one never used afterwards draws no warning.

                                  In these two forms a non-terminal may be declared without alternatives, nt : sort alone, for its rules to be added afterwards — rules computed from data, say, which a block cannot spell:

                                  smt.letGrammar! g ← s (x : Int) where
  start : Int := x | start + num
  num   : Int
let mut g := g
for k in [3, 7] do g ← g.addRule num (← Term.mkInt k)

                                  smt.grammar! refuses such a line, since the grammar it answers cannot be extended.

                                  A grammar can be extended until it is used for synthesis, after which cvc5 rejects new rules. A non-terminal unreachable from the start symbol is left out of the grammar until a rule reaches it.

                                  All three forms are scoped in each layer, as smt! is: open Cvc.Untyped selects this one.
